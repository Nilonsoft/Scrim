# Scrim v1.0.11 Feature Guide & Documentation

This document covers the new features, architecture enhancements, and operational guides introduced in Scrim version **1.0.11**.

---

## 1. Stream Relaying & Multi-DJ Party Hub

Scrim v1.0.11 introduces a comprehensive **Stream Relaying & Multi-DJ Party Hub** (`card-stream-relay`), enabling broadcasters to ingest external streams from guest DJs, sister radio stations, or remote co-hosts.

### Key Capabilities
- **Generic & Scrim-to-Scrim Ingest**:
  - Ingest standard MP3, AAC, Ogg, or FLAC HTTP streams via FFmpeg auto-reconnecting background decoders (`-reconnect 1 -reconnect_streamed 1 -reconnect_delay_max 5`).
  - **Auto-Detection for Scrim Sources**: If the remote source is another Scrim station, Scrim automatically detects the peer via `/api/branding` and stream HTTP headers (`X-Powered-By: Scrim`, `X-Scrim-Host`, `X-Scrim-Avatar`).
- **Remote DJ Name, Bio & Avatar Passthrough**:
  - In Scrim-to-Scrim mode, remote DJ names, bios, and avatars are dynamically displayed in the studio console.
  - With **Web Passthrough** enabled, remote DJ branding seamlessly flows into the web player via real-time Server-Sent Events (SSE), displaying the guest DJ's name and avatar to listeners while they are on air.
- **Pre-Fade Listen (PFL) Headphone Cueing**:
  - Dedicated `🎧 CUE` button on each ingested stream card.
  - Allows broadcasters to preview, monitor, and beatmatch guest DJ audio in headphones over dedicated WASAPI monitor audio device before bringing the guest on-air.
- **Stream Latency & Health Diagnostics**:
  - Real-time telemetry indicators calculate buffer depth and ping health (`EXCELLENT`, `GOOD`, `BUFFERING`, `UNSTABLE`).
  - Displays remote buffer latency in seconds (e.g. `(1.2s buffer)`).
- **Remote Track Metadata Passthrough**:
  - Scrim queries remote `/api/metadata` to detect the song title and artist currently playing on the guest DJ's decks.
  - Broadcasters can toggle **Track Passthrough** to seamlessly publish the guest DJ's track titles to web listeners and song history logs.
- **Automated B2B DJ Crossfader**:
  - Quick action buttons `⚡ Hand-Off to Guest (8s)` and `⚡ Take Back Decks (8s)`.
  - Executes smooth S-curve crossfades between host audio and guest relay streams over configurable durations (default: 8s), preventing abrupt cuts.
- **Private Green Room Talkback Intercom**:
  - `🎙️ TALKBACK (GREEN ROOM)` toggle button in the studio console.
  - When active, the host microphone is isolated from the master on-air broadcast sum (`TalkbackActive = true`), allowing private spoken coordination with guest performers off-air.
- **Fail-Safe Auto-Fallback on Stream Drop**:
  - If a guest DJ's connection drops unexpectedly, Scrim triggers `ActiveRelayDisconnected`, instantly restoring host deck audio volume to 100% and alerting the broadcaster in the studio console.
- **Listener Web Player Experience**:
  - **"Now on the Decks" / B2B Stage Presence Badge**: Visual dual-avatar cluster with glowing neon pulsing rings indicating which DJ is actively playing.
  - **DJ Hand-off Toast Banner**: Animated slide-in notification alerting listeners whenever the decks change hands.
  - **Guest DJ Profile Modal**: Popover dialog displaying the guest DJ's avatar, bio, and social links (Twitch, Discord, X/Twitter).
  - **Party Celebration Reactions**: Interactive `🎉 PARTY` button triggering floating celebratory confetti and pyro emoji bursts across listener screens via real-time SSE.
- **Dual Processing Modes**:
  - **Re-encoded Mix Deck**: Routes incoming relay audio directly into the native Pro DJ channel strip. The relay stream is smoothly ducked under local microphone announcements, shaped by the DJ 10-band EQ, blended with soundboard sound effects, and processed by the master limiter.
  - **Raw Passthrough**: Routes raw audio stream directly for low-CPU relaying.
- **Configurable Fade-In Duration**:
  - When connecting or engaging a remote stream, Scrim applies a smooth exponential fade-in curve (configurable between 0.5s and 10s) to prevent audio bursts or abrupt transitions.
- **Independent Gain & Mute Controls**:
  - Dedicated gain sliders (0% to 150%) and instant mute buttons for every ingested stream.

## 2. Dedicated Admin Settings Modal

App-level configurations are now consolidated into a centralized **Studio Settings** modal (`AdminSettingsModal.razor`), accessible via the `⚙️ Settings` button in the top navigation bar.

### Settings Tabs
1. **General & Scaling**:
   - High-DPI UI Scaling control (80% to 200%).
   - Auto-reconnect and monitoring options.
2. **Updates**:
   - Integrated with Scrim's update service. Broadcasters can manually trigger update checks, view the current version (`1.0.11`), and download new releases directly from GitHub.
3. **Audio Driver & WASAPI Setup**:
   - Status and configuration guidance for virtual audio cables (VB-Cable, Voicemeeter, VAC).
   - Audio buffer and sample rate configuration (standardized to 44.1kHz 16-bit stereo).
4. **Logs & Diagnostics**:
   - View recent application logs, crash reports, and system diagnostics without opening the file explorer.

## 3. High-DPI UI Scaling

Broadcasters on 4K, ultrawide, or high-density laptop displays can customize the UI scale directly from the Admin Settings screen or layout controls.
- Scale options range from **80% to 200%**.
- Applies uniform hardware-accelerated scaling via CSS zoom (`:root { zoom: ... }`) without compromising flexbox/grid layout alignments or drag-and-drop handles.
- Persisted automatically to the active venue profile in `ScrimProfile.UiScalePercentage`.

## 4. Collapsible Studio Cards

To maximize screen real estate and reduce visual clutter during live broadcasts, all 31+ cards now include an expand/collapse toggle (`−` / `+`) on their card headers.
- **Header Remains Visible**: The card header, title icon, drag handle, and quick controls stay accessible even when the card body is collapsed.
- **Per-Profile State Persistence**: The list of collapsed cards is automatically saved in `Profile.CollapsedCards`, restoring your exact workspace layout across sessions.

## 5. Stream Profile Manager for Venue Re-Use

Broadcasters frequently transition between different venues, clubs, or broadcast formats. Scrim v1.0.11 provides complete profile lifecycle management:
- **Topbar Profile Switcher**: Select between saved venue profiles instantly with the dropdown selector in the navigation bar.
- **Quick Save**: Save all current settings, cards, layouts, EQ gains, and branding to the active profile with one click.
- **Save As New Venue**: Clone current settings into a new venue profile (e.g., "Club Horizon", "Home Studio", "Festival Stage B").
- **Import & Export**:
  - Export profiles to `.json` files to share setups with other DJs or create offsite backups.
  - Import external `.json` profiles safely with automatic deduplication and validation.
- **Profile Deletion & Reset**: Delete obsolete profiles while protecting the default active profile from accidental deletion.

## 6. Stream Engine Overnight Auto-Recovery & Stability Fix

An issue was identified where stations running overnight in offline monitoring mode could fail to output audio when toggling "Start Broadcasting" online.

### Root Cause
Unconsumed channel buffers in `AudioDuckingMixer`, `ProcessLoopbackCapture`, and `MultiFormatTranscoder` accumulated millions of queued PCM frames during multi-hour offline monitoring. Upon broadcast start, the transcoder attempted to process gigabytes of backlogged audio, stalling real-time streaming.

### The Fix
1. **Bounded Audio Channels**: Converted mixer, capture, and transcoder queues to bounded channels using `BoundedChannelFullMode.DropOldest` (capacity: 100 frames / ~2 seconds max).
2. **Buffer Flush on State Transitions**: `FlushOutput()` and `FlushChannel()` are explicitly called on broadcast start and stop to ensure a zero-latency, fresh audio stream.
3. **WASAPI Auto-Recovery**: If a Windows audio device resets or sleeps overnight, `ProcessLoopbackCapture` auto-detects `RecordingStopped` and smoothly re-initializes loopback capture.
4. **Web Player Auto-Sync**: The embedded web player listener monitors broadcast live events (`data.isLive: true`) via SSE and automatically resumes playback without requiring manual browser reloads.

## 7. Audio Visualizer Reaction Modes ("Reactors") Customization

Station owners can fully curate which visualizer reaction modes ("reactors") are presented to listeners on the web player:
- **Built-in Reactor Presets**:
  - `📊 Bars` (Classic logarithmic frequency equalizer bars)
  - `📈 Wave` (Smooth oscilloscope waveform monitor)
  - `🌈 Spectrum` (Harmonic multi-frequency spectrum curves)
  - `✨ Pulse` (Rhythmic radial bass pulsation and sound rays)
- **Hide / Show Control**:
  - Broadcasters can toggle `IsEnabled` on any reactor. Built-in reactors can be hidden without deleting their presets.
- **Default Visualizer Mode**:
  - Designate which reactor mode activates automatically when a listener first tunes in.
- **Custom Reactor Creation & Deletion**:
  - Add custom presets with custom labels, emojis, and base reaction engines (`bars`, `wave`, `spectrum`, `pulse`).
  - Delete custom presets when no longer needed.
- **Dynamic Web Player Sync**:
  - Changes made in the studio console are broadcast via real-time SSE (`branding` event) and `/api/branding`, instantly re-rendering listener visualizer toolbars without browser refreshes.

## 8. Backstage DJ & Green Room Private Chat

In addition to the off-air audio talkback intercom, Scrim v1.0.11 includes a dedicated **Backstage DJ & Green Room Private Chat**:
- **Private Off-Air Coordination**:
  - Studio hosts and guest DJs can exchange cues, track BPMs, harmonic keys, and hand-off timings privately.
  - Completely isolated from public listener chat (`/api/chat`).
- **In-Console Studio Panel**:
  - Integrated directly inside `Stream Relaying & Multi-DJ Party Hub` (`card-stream-relay`).
  - Displays formatted timestamps, color-coded sender names, host badges, and auto-scrolls to the latest notes.
- **Real-Time API & Web Interconnect**:
  - Exposed via `/api/greenroom/chat` GET and POST endpoints.
  - Real-time instant delivery across connected performers via SSE `greenroom_chat` events.
  - In-memory rolling ring buffer capped at 50 messages to preserve zero-latency performance without external database overhead.
